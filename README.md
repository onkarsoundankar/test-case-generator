# AI-Powered Test Case Generator from User Stories

Reads a user story (pasted text, a text file, or fetched directly from Jira),
finds similar past stories/test cases from a local knowledge base, and uses
Claude to generate structured BDD/Gherkin test cases (functional, edge, and
negative scenarios).

## What's inside

```
test-case-generator/
├── src/
│   ├── corpus/sample_stories.json   # sample "past" stories + test cases (the RAG knowledge base)
│   ├── build_index.py               # turns the corpus into a searchable vector index (run once)
│   ├── retriever.py                 # finds similar past stories for a new story
│   ├── generator.py                 # calls Claude to write the test cases
│   ├── jira_client.py               # optional: pulls a story directly from Jira
│   └── main.py                      # the command-line tool you actually run
├── eval/evaluate.py                 # compares AI output vs. a manually-written reference
├── vector_index/                    # generated by build_index.py (created automatically)
├── output/                          # generated test cases land here
├── requirements.txt
└── .env.example
```

## How it works (plain English)

1. You give it a user story.
2. It searches a small local library of past stories to find similar ones (this is the "RAG" part — Retrieval-Augmented Generation).
3. It sends your story + those similar examples to Claude, asking it to write Gherkin-format test cases.
4. It saves the result as a `.feature` file you can hand to QA or drop into a test framework like Cucumber/Behave.

## Step-by-step setup (MacBook Air M1)

### 1. Check you have Python 3.10+

```bash
python3 --version
```
If it's below 3.10, install a newer version via [python.org](https://www.python.org/downloads/) or `brew install python@3.12`.

### 2. Unzip/place the project folder

Put the `test-case-generator` folder anywhere, e.g. your Desktop, then open Terminal and go into it:

```bash
cd ~/Desktop/test-case-generator
```

### 3. Create a virtual environment (keeps this project's packages separate from the rest of your system)

```bash
python3 -m venv venv
source venv/bin/activate
```

You'll know it worked because your terminal prompt now starts with `(venv)`.

### 4. Install dependencies

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

This installs: the Anthropic SDK (to call Claude), `sentence-transformers` + `faiss-cpu` (for local search — these run fine on M1, no GPU needed), and a couple of small helper libraries. This step may take a few minutes and download ~500MB-1GB (mostly PyTorch, used by sentence-transformers).

### 5. Get an Anthropic API key

- Go to https://console.anthropic.com/settings/keys
- Create a key (you'll need billing set up — this is pay-as-you-go, generation calls here cost fractions of a cent to a few cents each)

### 6. Set up your `.env` file

```bash
cp .env.example .env
```

Open `.env` in any text editor and paste your real key:

```
ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxx
```

(Leave the Jira lines blank unless you plan to use the Jira integration — see below.)

### 7. Build the vector index (run once)

This reads the sample stories and turns them into searchable vectors:

```bash
python src/build_index.py
```

Expected output:
```
Loaded 6 stories from corpus.
Loading embedding model 'all-MiniLM-L6-v2' (first run downloads it, ~80MB)...
Encoding stories into vectors...
Index built with 6 vectors.
Saved index to: .../vector_index/stories.index
```

### 8. Generate your first test cases!

```bash
python src/main.py --story "As a user, I want to update my email address in account settings so that I can keep my contact info current." --acceptance-criteria "User can change email to a new valid address;System sends a verification link to the new email;Email is not updated until verified;Duplicate emails are rejected" --test-types functional,edge,negative
```

You'll see it:
1. Print which similar past stories it matched
2. Call Claude to generate the test cases
3. Save a `.feature` file into `output/`
4. Print the result to your terminal

Example output (abbreviated):

```gherkin
Feature: Update account email address

  Scenario: Successfully update email with valid new address
    Given a logged-in user is on the account settings page
    When the user enters a new valid email address
    And submits the change
    Then a verification link is sent to the new email address
    And the email is not yet updated

  Scenario: Reject duplicate email already in use
    Given a logged-in user attempts to change their email
    When they enter an email address already registered to another account
    Then an error message "This email is already in use" is displayed

  Scenario: Email update remains pending until verified
    Given a user has requested an email change
    When they have not yet clicked the verification link
    Then their account email remains unchanged
```

### 9. Other ways to run it

**From a text file:**
```bash
python src/main.py --story-file my_story.txt
```

**From Jira directly** (needs `JIRA_URL`, `JIRA_EMAIL`, `JIRA_API_TOKEN` filled in `.env` — the token comes from https://id.atlassian.com/manage-profile/security/api-tokens):
```bash
python src/main.py --jira-key PROJ-123
```

**Choosing test types** (smoke = quick happy-path only, regression = thorough, exploratory = creative edge-hunting):
```bash
python src/main.py --story-file my_story.txt --test-types smoke
```

**Free mode (no API credits needed):**
```bash
python src/main.py --story-file my_story.txt --mock
```

**Print a copy-pasteable prompt for the free claude.ai chat instead of paying for the API:**
```bash
python src/main.py --story-file my_story.txt --print-prompt
```

## Demoing this to someone (a browser UI instead of Terminal)

For a demo, use the web app instead of the command line — it's the same pipeline, but click-based:

```bash
streamlit run src/app.py
```

This opens `http://localhost:8501` in your browser automatically. From there you can:
- Type a story into a text box
- Pick test types with checkboxes
- Click "Generate Test Cases"
- See the retrieved similar stories and the generated Gherkin output right on the page
- Download the result as a `.feature` file

**Important:** this only runs on your own laptop. If your manager is in the same room or on a screen-share, this is a great demo. If your manager needs to open a link from *their own* computer without you present, that requires actually deploying the app to the internet (see below).

### Deploying so anyone can visit a real URL (optional, extra setup)

If you want a public link you can just send someone:

1. Push this project to a GitHub repository (create a free GitHub account if you don't have one, create a new repo, upload these files)
2. Go to https://share.streamlit.io (Streamlit Community Cloud — free tier)
3. Sign in with GitHub, click "New app", point it at your repo and `src/app.py`
4. Add your `ANTHROPIC_API_KEY` under the app's "Secrets" settings (only if you want real AI mode available online — otherwise leave mock mode as default)
5. Deploy — you'll get a URL like `https://yourapp.streamlit.app` that works from any browser, anywhere

This step is optional and only needed if you want a truly shareable link rather than a local demo.

### 10. Evaluate AI output vs. a human-written version

If you (or a teammate) also write test cases manually for the same story, you can compare:

```bash
python eval/evaluate.py --generated output/test_cases_20260101_120000.feature --manual manual_reference.feature
```

This gives you a rough coverage % (did the AI catch the topics the human covered?) and flags likely gaps. It's a heuristic, not a certification — always have a human do a final review.

## Adding your own real stories to the knowledge base

Edit `src/corpus/sample_stories.json` and add more entries in the same format (title, story, acceptance_criteria, test_cases), using your team's real past stories and test cases. Then re-run:

```bash
python src/build_index.py
```

The more real examples you add, the better the AI's style/structure matching gets.

## Troubleshooting

- **"Vector index not found"** → run `python src/build_index.py` first.
- **Anthropic API errors about the key** → double check `.env` has no quotes around the key and no trailing spaces.
- **`pip install` fails on M1** → make sure you're using the venv's pip (`which pip` should show a path inside `venv/`), and that you're on Python 3.10+.
- **Jira fetch fails** → confirm `JIRA_URL` has no trailing slash issues and your API token is valid.
